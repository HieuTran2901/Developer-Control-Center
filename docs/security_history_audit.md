# Security History - Architecture Audit Report

## 1. Executive Summary & Existing Lifecycle Trace
The Security Scan System communicates between Rust Backend and React Frontend via Tauri IPC events (`security_event`), dispatched through the frontend `EventBus`.

### Security Event Lifecycle:
1. **Started**: Emitted when a scan session is registered (`scan_id`, `project_id`).
2. **Progress**: Emitted periodically during file traversal (`scanned_files`, `current_scanner`).
3. **FindingsChunk**: Emitted when findings are detected in batches (`findings: SecurityFinding[]`).
4. **Completed**: Emitted upon successful scan completion (`scan_id`, `summary: SecurityScanSummary`).
5. **Failed**: Emitted on runtime panic or task failure (`scan_id`, `reason`).
6. **Cancelled**: Emitted when a scan is manually stopped (`scan_id`).

### Audit Findings:
- **Scan Completion Criteria**: A scan session finishes when `Completed`, `Failed`, or `Cancelled` is published.
- **Idempotency Key**: `scan_id` uniquely identifies each scan session.
- **Data Location Options**:
  - `ApplicationStateService` & `IDesktopGateway` currently use Tauri AppData directory (`%APPDATA%/com.trongminh.developer-control-center/`).
  - Persistent storage path on `E:` drive (e.g. `E:\Developer-Control-Center\data\security-history\history.json`) or AppData fallback cleanly abstracted in `SecurityHistoryRepository`.
- **Privacy & Secret Protection**: All secret findings generated by `CoreSecretScanner` already go through `DefaultRedactor` or pattern-specific masking (`RedactedEvidence`), ensuring evidence strings in findings never store raw plaintext secrets.

## 2. Security History Record Schema Proposal
Each persistent record stored in the repository will contain:

```typescript
export interface SecurityHistoryRecord {
  id: string; // Idempotency key (scanId)
  scanId: string;
  projectId?: string;
  targetName: string;
  targetPath: string;
  scanMode: SecurityScanMode;
  status: 'COMPLETED' | 'FAILED' | 'CANCELLED';
  startedAt: number; // Unix timestamp (ms)
  completedAt: number; // Unix timestamp (ms)
  durationMs: number;
  scannedFiles: number;
  summary: SecurityScanSummary;
  reason?: string; // If FAILED
}
```

## 3. History Retention & Storage Architecture
- **Storage Abstraction**: `SecurityHistoryRepository` operating via `IDesktopGateway` (`readTextFile`/`writeTextFile`).
- **Idempotency**: Check `scanId` existence before adding a record.
- **Retention Policy**: Maximum **100 records**. When exceeding 100 records, older entries are automatically purged.
- **UI Tab Integration**: `SecurityOverview.tsx` History tab will subscribe to history updates and render standard history items showing Scan Mode, Target, Timestamp, Duration, Status, and Severity Breakdown badge metrics.
